# 交付前自检清单

在输出完成结论之前逐项核对。P0 为阻断项，任一未满足即不得宣称完成；P1 为建议项，未满足时在报告中说明原因。

## P0 阻断项

- [ ] 依赖方向：domain 无框架 import、无对其他层的 import；infrastructure 不反向依赖上层。
- [ ] 领域模型：聚合根有私有构造与行为方法，无公共 setter，集合返回不可变，业务不变式在聚合内校验。
- [ ] 聚合边界：一个事务只改一个聚合，聚合间只用 ID 引用，跨聚合用领域事件。
- [ ] 事务边界：`@Transactional` 只在 application，事务内无远程调用与消息发送。
- [ ] 持久化隔离：PO / ORM 注解只在 infrastructure，仓储接口只使用领域类型，转换在 infrastructure 完成。
- [ ] 接口边界：领域对象与 PO 未作为 HTTP 请求 / 响应体；Controller 未注入 Repository / Mapper。
- [ ] 类型与语法：金额用 BigDecimal、时间用 java.time、语法不超过项目 Java 版本、无未声明依赖。
- [ ] 异常与日志：无空 catch、无 `System.out`、无敏感信息日志、业务失败有明确错误码。
- [ ] 无占位实现：无空方法、无返回固定值、无遗留 TODO 桩、无整文件重写、无无关文件改动。
- [ ] 测试：新增功能有对应测试，且覆盖至少一条失败路径。
- [ ] 门禁：`check_changes.py` 无 BLOCK；`lint_gate.py` 编译与测试通过；未执行项已如实标注。
- [ ] 报告：改动清单、实际命令与结果、默认假设 / 冲突 / 未决项三段齐全。

## P1 建议项

- [ ] 命名与包结构与项目同类文件一致；无新增无意义 `Util` / `Manager` 类。
- [ ] 值对象不可变且覆盖 `equals` / `hashCode`。
- [ ] 领域事件在事务提交后发布，消费者幂等。
- [ ] 写用例具备幂等键，并发修改有乐观锁策略。
- [ ] 参数校验按 interfaces / application / domain 三层归位。
- [ ] 转换器纯映射、无业务规则，枚举映射显式。
- [ ] 注释解释 why，未提交注释掉的代码块。
- [ ] 有 ArchUnit 分层守护；项目没有时已在报告中提出建议。
- [ ] 新增或修改超过 5 个文件时，已先把改动清单交给用户确认。

